How many customers pay the rent?

A general-purpose version of an internal profitability simulator. The report takes a handful of assumptions about customers, usage, price and costs. It answers three questions: how many customers cover the fixed costs, in which month the margin turns positive, and when the early losses are paid back. Every setting lives in the URL, so a link is the whole report.

The model

One month, repeated

This is the reference simulator's arithmetic with a generic vocabulary: a customer buys units, and both nouns can be renamed through the URL. Two optional revenue and cost lines are added: a flat subscription per customer, and an acquisition cost per new customer. All money is held as integer cents. Prices include VAT, so VAT is taken out of revenue and never out of costs.

// per month m = 1..months
units        = round(customers × unitsPerCustomer)
revenue      = net(units × price + round(customers) × subscription)   // VAT on the month, not per unit
variableCost = units × variable
acquisition  = newCustomers(m) × cac          // month 1 buys no one
margin       = revenue − variableCost − acquisition − fixed
cumulative  += margin
customers    = customers × (1 − churn%) + growth   // kept fractional, rounded for display

net(gross)          = floor(gross / (1 + vat%))
contribution        = unitsPerCustomer × (price ÷ (1 + vat%) − variable) + subscription ÷ (1 + vat%)
breakEvenCustomers  = contribution ≤ 0 ? never : ceil(fixed / contribution)
breakEvenMonth      = first m with margin ≥ 0
paybackMonth        = first m ≥ breakEvenMonth with cumulative ≥ 0
marginRate          = totalMargin / totalRevenue        // new; the reference has no margin %
revenue excl. VAT costs cumulative margin

Defaults below over 24 months. Break-even month and payback month are marked on the chart. The figures are computed live on this page from the formulas above.

Query contract

The URL is the report

Values are parsed with defaults and clamped to their range. Anything out of range or not a number falls back to its default, and a warning chip appears on the report. When a link is shared, only the values that differ from the defaults are written, so the default report is just /. Money is written in major units in the URL, for example price=0.25, and converted to cents at parse time.

Stack & standing specs

Stack

  • Next.js 16 static export on Bun with Tailwind v4, shadcn primitives and Recharts; unit tests with bun test, end-to-end tests with Playwright. TDD for the engine and the query codec.
  • SOLID layout. domain/ holds the pure engine, query/ the parse and serialize codec, export/ the JSON and CSV builders, and app/ the UI. The UI depends on the engine's types and nothing else.
  • Served by nginx. Access and error logs are one JSON object per line, with the error-log level set by LOG_LEVEL in .env. Each request carries an x-trace-id: a valid inbound id is kept, otherwise nginx's $request_id is used. The id is written into every log line and sent back on the response.
  • Docker multi-stage image: Bun builds the site and nginx serves it, a compose file with a healthcheck, and the port taken from freeport in development.
  • README.md, CLAUDE.md and TODO.md, all in English. One commit per iteration, and a review after each phase.
